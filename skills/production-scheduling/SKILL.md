# 生产排程

先阅读 [命令手册](references/commands.md)。手册包含本 skill 的全部命令、字段、默认值和 JSON 示例；不要探测命令帮助。

## 工作方式

1. 先确认 APS 地址和当前账号可用，再查询待排订单、班组和现有排产记录。
2. 自动排产一律先试算。试算会返回可比较的候选方案；在 WorkBuddy 中不指定输出时会自动附上正式 HTML 甘特图。
3. 用业务语言说明推荐方案与当前采用方案的交期、未排数量、拆单和约束差异。明确说“试排方案，尚未保存”。
4. 只有用户确认后，使用试算返回的 `previewToken` 和其明确选定的求解方案提交。不得重新计算后替换用户已确认的方案。
5. 锁定、批量调整、移动和删除同样先说明受影响订单或排产记录，再获得确认。删除须精确 ID 与 `--yes`。

## 业务沟通

- 成功时先说明涉及的订单、班组、日期和数量，随后说明是否已保存。
- 容量不足、齐套未满足、数据已变化或方案过期时，说明具体业务影响并建议重新试排、调整产能或处理齐套问题。
- 不在面向业务用户的回复中提及命令、接口、参数、协议、原始错误或堆栈；只有用户明确要求技术排查时才提供经过脱敏的诊断。
